# Stress-testing a static contribution recommendation

```sh
bin/yieldcraft-inventory build
bin/yieldcraft-inventory stress-contribution scenario.csv valuation.csv demand.csv stress.csv
```

Pass a frozen `pricing.demand@1` snapshot from the [existing first-party estimator](YIELDCRAFT_DEMAND.md) or a compatible producer. This planner doesn't re-estimate demand. It checks the scenario digest, currency, price basis, evidence tagging, freshness and cutoff using the same rules as the point-estimate contribution policy. It applies the floor/cap and movement guardrails from the valuation.

Create `stress.csv` with the exact rows below. Replace `DEMAND_DIGEST` with the bare BLAKE3 of the full demand CSV bytes (the estimator's `evidence` command prints it as `demand`, prefixed with `blake3:`), and use your own prices, bounds, and assumption clock.

```csv
pricing.demand-stress-input@1
demand_blake3,assumptions_as_of
DEMAND_DIGEST,2026-11-20T10:00:00Z
price_minor,low_room_nights_milli,high_room_nights_milli
16000,35000,60000
17500,20000,50000
19000,10000,40000
```

These quantities are illustrative, **not statistical confidence bounds**. Provide each and every demand arm in the same order. Each supplied interval must contain the nominal expected quantity; each endpoint curve must be nonincreasing and in `[0, 1000000]` thousandths of a room-night. `assumptions_as_of` is a declared UTC time, constrained to the interval between demand ingestion and the decision cutoff. The tool does not independently authenticate the clock or validate the assumed intervals against observations.

Output [`pricing.contribution-stress@1`](../contracts/pricing.contribution-stress@1.schema.json) is a separate unpublished JSON report. Each price and marginal cost uses EUR minor units per room-night. Modeled contribution is `(price − marginal cost) × quantity` in milli-minor EUR; the adverse endpoint uses low quantity for positive margin and high quantity for negative margin. Maximize the worst-case score over feasible arms, and also report the nominal-score optimizer for comparison. Hold has zero flow and wins against all nonpositive scores. Positive ties favor the nearest price to current, then the lower price. There is no opportunity cost, realized uplift, simultaneous cross-price inference, booking probability, or claim that zero is the true cost of holding; use the [separate inventory planner](YIELDCRAFT_COUPLED_INVENTORY.md) where stock displacement or terminal value matters. Reported input digests make the result reproducible from the four exact files; this is not an archived recommendation or authorized price action.

`python3 -B tests/check_yieldcraft_risk_contribution.py` exercises the CLI with a typed demand snapshot generated by the unchanged estimator, and compares every candidate and both selected actions with independent endpoint enumeration.
